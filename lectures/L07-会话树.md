## 详细讲解

### 1. SessionEntry 类型体系

Pi 采用统一的 `EntryBase` + 类型判别式模式，所有条目共享 `id`、`parentId`、`seq`、`timestamp` 四个字段：

```typescript
interface EntryBase {
  type: string;
  id: string;
  seq: number;              // 全局序列号，存储层分配
  parentId: string | null;  // 存储层分配：当前 lane 的 leafId
  timestamp: number;        // Unix ms，存储层分配
}
```

#### 7 种 Entry 类型

```typescript
// 1. 消息条目 — 最核心，承载对话内容
interface MessageEntry extends EntryBase {
  type: "message";
  message: AgentMessage;
  terminate?: true;
}

// 2. 模型切换 — 记录 provider/modelId 变更
interface ModelChangeEntry extends EntryBase {
  type: "model_change";
  provider: string;
  modelId: string;
}

// 3. 思考级别变更
interface ThinkingLevelEntry extends EntryBase {
  type: "thinking_level_change";
  thinkingLevel: string;
}

// 4. 活跃工具变更
interface ActiveToolsEntry extends EntryBase {
  type: "active_tools_change";
  activeToolNames: string[];
}

// 5. 压缩条目 — 长对话摘要
interface CompactionEntry extends EntryBase {
  type: "compaction";
  summary: string;
  retainedTail: AgentMessage[];  // 保留的尾部消息
  tokensBefore: number;          // 压缩前 token 数
  details?: unknown;
  usage?: Usage;
}

// 6. 分支摘要 — 子分支的压缩总结
interface BranchSummaryEntry extends EntryBase {
  type: "branch_summary";
  fromId: string;       // 摘要起始节点
  summary: string;
  details?: unknown;
  usage?: Usage;
}

// 7. 自定义条目 — 扩展用途
interface CustomEntry extends EntryBase {
  type: "custom";
  customType: string;   // 自定义类型标识
  data?: unknown;
}

type Entry =
  | MessageEntry
  | ModelChangeEntry
  | ThinkingLevelEntry
  | ActiveToolsEntry
  | CompactionEntry
  | BranchSummaryEntry
  | CustomEntry;
```

#### ProvisionedEntry — 写入前的"半成品"

写入时 `parentId`、`seq`、`timestamp` 由存储层自动填充，所以写入方只需要提供"半成品"：

```typescript
type ProvisionedEntry<TEntry extends Entry> = Omit<TEntry, "parentId" | "seq" | "timestamp">;
```

这意味着调用 `appendMessage()` 时，只需传 `{ type: "message", id, message }`，三个存储层字段会自动补全。

### 2. Append-Only 特性

```
原始数据：
hdr → usr1 → ass1 → tool1 → ass2
                ↓
              usr2 → ass3

特点：
- 零删除：所有历史数据都保留
- 零复制：新分支直接引用父节点
- 高效追加：只追加新条目
- 顺序编号：seq 全局递增，提供时间线视图
```

### 3. 树结构构建

```typescript
function buildTree(entries: SessionEntry[]): Map<string, SessionEntry[]> {
  const children = new Map<string, SessionEntry[]>();

  for (const entry of entries) {
    const parentId = entry.parentId ?? "root";
    if (!children.has(parentId)) {
      children.set(parentId, []);
    }
    children.get(parentId)!.push(entry);
  }

  return children;
}
```

### 4. Lane（分支通道）系统

Lane 是 Pi 实现多分支并行的核心抽象。每个 Lane 有独立的 `leafId`（当前写入点），可以独立追加、移动。

```typescript
interface LanePointer {
  lane: string;           // 通道名称，如 "main"
  leafId: string | null;  // 当前叶子节点，空表示通道为空
}
```

#### 核心操作

```typescript
class Session {
  // 获取所有 Lane
  async getLanes(): Promise<LanePointer[]>

  // 创建新 Lane，at 指定分叉点（null 表示从头开始）
  async createLane(lane: string, at: string | null): Promise<void>

  // 移动 Lane 的叶子节点（回退或跳转）
  async moveLane(lane: string, to: string | null): Promise<void>

  // 为某个 Lane 创建视图，所有读写操作都限定在该 Lane 内
  view(lane: string): SessionTree
}
```

#### view(lane) — Lane 视图

`view()` 返回一个 `SessionTree`，所有操作自动限定在指定 Lane 内：

```typescript
view(lane: string): SessionTree {
  if (lane === "main") return this;  // 主通道直接返回自身
  return {
    getLeafId: () => this.getLeafIdForLane(lane),
    findEntriesOnBranch: (query) => this.queryBranchEntries(lane, query),
    appendMessage: (message) => this.appendMessageToLane(lane, message),
    appendCustomEntry: (type, data) => this.appendCustomEntryToLane(lane, type, data),
    // ... 其他方法同理
  };
}
```

**设计意义**：通过 Lane 视图，主通道和分支通道可以并行写入，互不干扰。

### 5. Label 标签系统

Label 是附着在任意 Entry 上的元数据标记，与 Entry 本身解耦：

```typescript
class Session {
  async getLabel(targetId: string): Promise<string | undefined>
  async setLabel(targetId: string, label: string | undefined): Promise<void>
}
```

**用途**：
- 标记用户确认的检查点（`"confirmed"`）
- 标记错误节点（`"error"`）
- 标记分支选择（`"selected"`）
- 自由扩展，值是任意字符串

Label 是全局的，不按 Lane 隔离。

### 6. SessionStorage 抽象存储层

Session 类本身不持有任何数据，所有持久化操作委托给 `SessionStorage` 接口：

```typescript
interface SessionStorage<TMetadata extends SessionMetadata> {
  getMetadata(): Promise<TMetadata>;

  // Lane 管理
  getLanes(): Promise<LanePointer[]>;
  createLane(lane: string, at: string | null): Promise<void>;
  moveLane(lane: string, to: string | null): Promise<void>;

  // 写入
  appendEntry<TEntry extends Entry>(entry: ProvisionedEntry<TEntry>, lane: string): Promise<TEntry>;
  appendRecord<TRecord extends LaneRecord>(record: NewRecord<TRecord>): Promise<TRecord>;

  // 读取
  getEntry(id: string): Promise<Entry | undefined>;
  findEntries(query?: EntryQuery): Promise<Entry[]>;
  findEntriesOnBranch(query: EntryQuery & BranchBounds & { start: string }): Promise<Entry[]>;
  findRecords(query?: RecordQuery): Promise<LaneRecord[]>;
  findOpenOperations(lane: string, options?: { limit?: number }): Promise<OperationStartedRecord[]>;
  getLog(options?: LogOptions): Promise<LogItem[]>;

  // 全局事实
  getName(): Promise<string | undefined>;
  setName(name: string | undefined): Promise<void>;
  getLabel(id: string): Promise<string | undefined>;
  setLabel(id: string, label: string | undefined): Promise<void>;
  getStats(): Promise<SessionStats>;
}
```

**架构意义**：Session 是门面（Facade），Storage 是策略（Strategy）。可以替换为 JSONL、SQLite、Durable Objects 等不同实现。

### 7. assertJsonSerializable 序列化校验

所有写入操作（`appendEntry`、`appendRecord`）都会先经过此校验，确保数据可安全序列化为 JSON：

```typescript
function assertJsonSerializable(value: unknown): void {
  // 使用 WeakSet 检测循环引用
  // 使用栈（非递归）避免深层嵌套爆栈
}
```

**校验规则**：
| 规则 | 拒绝原因 |
|------|---------|
| `NaN` / `Infinity` | "contains a non-finite number" |
| 循环引用 | "contains a cycle" |
| `Map`、`Set` 等非标准对象 | "contains a non-standard array" |
| Symbol 属性 | "contains a symbol-keyed property" |
| getter/setter | "contains an accessor" |
| 稀疏数组 | "contains a sparse array" |
| 非纯对象（原型链非 Object） | "contains a non-plain object" |

**为什么用栈而非递归？** 深层嵌套（如 10000 层）会爆栈，栈方式可处理任意深度。

### 9. Record 系统 — 操作日志

Record 与 Entry 的区别：Entry 是"数据"，Record 是"操作日志"。Record 按 Lane 独立编号，用于追踪操作流程。

```typescript
interface RecordBase {
  id: string;
  seq: number;       // Lane 内顺序编号
  lane: string;      // 所属 Lane
  timestamp: number;
}
```

### 12. 路径遍历

```typescript
function traversePath(entries: SessionEntry[], leafId: string): SessionEntry[] {
  const entryMap = new Map(entries.map((e) => [e.id, e]));
  const path: SessionEntry[] = [];
  let currentId: string | null = leafId;

  while (currentId) {
    const entry = entryMap.get(currentId);
    if (!entry) break;
    path.unshift(entry);
    currentId = entry.parentId;
  }

  return path;
}
```

### 13. 分支机制

```
主分支:  hdr → usr1 → ass1 → tool1 → ass2
分支点:  ass1
分支:    ass1 → usr2 → ass3

Lane 视图：
- main   leafId → ass2
- branch leafId → ass3
```

通过 `createLane("branch", ass1.id)` 创建分支通道，`view("branch")` 获取该分支的写入视图。

function calculateCost(entries: SessionEntry[]): number {

    .filter((e): e is AssistantEntry => e.type === "assistant")
    .reduce((sum, e) => sum + (e.usage?.cost ?? 0), 0);

## 架构总览

```
Session (门面)
  │
  ├── Entry 写入  → assertJsonSerializable → Storage.appendEntry
  ├── Record 写入 → assertJsonSerializable → Storage.appendRecord
  ├── Entry 查询  → Storage.findEntries / findEntriesOnBranch
  ├── Record 查询 → Storage.findRecords
  ├── Lane 管理   → Storage.getLanes / createLane / moveLane
  ├── Label 管理  → Storage.getLabel / setLabel
  ├── Log 视图    → Storage.getLog
  └── view(lane)  → 返回限定 Lane 的 SessionTree 子集
```

**核心设计原则**：
1. **Entry 是数据，Record 是日志** — 分离关注点
2. **Storage 是策略，Session 是门面** — 实现可替换
3. **Lane 是隔离单元** — 多分支并行写入
4. **Assert 是安全网** — 写入前校验序列化安全性

**题目**：实现一个函数，统计 CompactionEntry 的压缩效果（压缩前后 token 比）。

**参考答案**：

```typescript
function compactionRatio(entries: Entry[]): { compressed: number; avgRatio: number } {
  const compactions = entries.filter((e): e is CompactionEntry => e.type === "compaction");
  if (compactions.length === 0) return { compressed: 0, avgRatio: 0 };

  const ratios = compactions.map((c) => {
    const afterTokens = c.retainedTail.length;  // 简化：用消息数近似
    return c.tokensBefore / Math.max(afterTokens, 1);
  });

  return {
    compressed: compactions.length,
    avgRatio: ratios.reduce((a, b) => a + b, 0) / ratios.length,
  };
}
```
