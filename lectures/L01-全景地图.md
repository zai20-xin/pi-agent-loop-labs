# L01 全景地图

## 讲次标题
**Pi 项目架构全景：四层积木如何搭出一个 97k Stars 的终端编程 Agent**

## 一、Pi 项目是什么

Pi 是一个开源的终端 AI 编程助手，采用 monorepo 架构，核心代码约 10 万行 TypeScript。它不是简单的 CLI wrapper，而是一个完整的 **Agent 系统**——能自主读代码、写代码、执行命令、管理会话。

```
pi-monorepo/
├── packages/
│   ├── ai/               # L1: 统一模型层
│   ├── agent/            # L2: Agent Loop 引擎
│   ├── coding-agent/     # L3: 编程 Agent 实现
│   ├── tui/              # L4: 终端 UI
│   ├── protocol/         # CBOR 传输协议
│   ├── client/           # 远程会话客户端
│   ├── server/           # 远程会话服务端
│   ├── telemetry/        # 遥测/可观测性
│   ├── evals/            # 评测框架
│   └── session-backends/ # 会话存储后端
```

**技术栈**：TypeScript 5.9 / Node ≥22.19 / ESM / Vitest / Biome / tsgo（原生 TS 编译器）

---

## 二、四层积木架构

Pi 的设计哲学是 **积木式分层**：每层只依赖下层，不反向依赖。

```
┌─────────────────────────────────────────────────┐
│  L4: pi-tui          终端 UI 差分渲染          │
│  组件树 / Markdown / 图片 / 键绑定             │
├─────────────────────────────────────────────────┤
│  L3: pi-coding-agent 编程 Agent 实现           │
│  工具(read/bash/edit/write) / 会话管理 / 扩展  │
├─────────────────────────────────────────────────┤
│  L2: pi-agent-core   Agent Loop 引擎          │
│  循环 / 事件流 / 工具执行 / 上下文管理         │
├─────────────────────────────────────────────────┤
│  L1: pi-ai           统一模型层               │
│  多厂商 API / 模型目录 / 流式 / 鉴权           │
└─────────────────────────────────────────────────┘
```

### 依赖方向

```
coding-agent → agent-core → pi-ai
     ↓                          ↑
    tui ─────────────────────────┘
```

## 三、L1: pi-ai — 统一模型层

**职责**：屏蔽 OpenAI / Anthropic / Google / Bedrock 等厂商 API 差异，提供统一的 `Model` + `streamSimple` 接口。

### 核心文件

| 文件 | 职责 |
|------|------|
| `src/index.ts` | 统一导出：Model、Context、EventStream、工具验证 |
| `src/models.ts` | `Model<TApi>` 类型定义，模型元数据结构 |
| `src/types.ts` | `Message` / `AssistantMessage` / `ToolResultMessage` 等消息类型 |
| `src/models-store.ts` | 运行时模型注册与发现 |
| `src/session-resources.ts` | 会话级资源管理（API key 缓存等） |
| `src/api/openai-responses.ts` | OpenAI Responses API 实现 |
| `src/api/anthropic-messages.ts` | Anthropic Messages API 实现 |
| `src/api/google-generative-ai.ts` | Google Generative AI 实现 |
| `src/api/bedrock-converse-stream.ts` | AWS Bedrock 实现 |
| `src/providers/` | 87 个模型提供商定义（OpenAI、Anthropic、DeepSeek、Qwen 等） |
| `src/auth/` | OAuth / API Key 鉴权 |
| `src/utils/event-stream.ts` | `EventStream<TEvent, TResult>` 通用流式抽象 |

### 关键概念

```typescript
// 统一模型接口
interface Model<Api> {
  id: string;
  name: string;
  api: Api;           // "openai-responses" | "anthropic-messages" | ...
  provider: string;   // "openai" | "anthropic" | "google" | ...
  contextWindow: number;
  maxTokens: number;
  reasoning: boolean; // 是否支持 thinking
}

// 统一流式调用
const response = await streamSimple(model, { systemPrompt, messages, tools }, options);
for await (const event of response) { ... }
const finalMessage = await response.result();
```

**本层不依赖任何上层包。它是整个系统的地基。**

## 四、L2: agent-core — Agent Loop 引擎

**职责**：实现 **通用** Agent Loop——LLM 调用 → 工具执行 → 结果回传 → 循环。不关心具体工具是什么（读文件？查天气？），只定义循环协议。

### 核心文件

| 文件 | 行数 | 职责 |
|------|------|------|
| `src/agent-loop.ts` | ~800 | **核心循环**：`agentLoop()` / `agentLoopContinue()` / `runLoop()` |
| `src/agent.ts` | ~600 | **Agent 类**：有状态包装器，管理订阅、队列、生命周期 |
| `src/types.ts` | ~440 | `AgentLoopConfig` / `AgentEvent` / `AgentTool` / `AgentContext` |
| `src/stream-fn.ts` | ~30 | 默认流函数设置 |
| `src/proxy.ts` | - | 代理工具 |
| `src/search/` | - | 搜索工具 |
| `src/harness/` | - | 测试/调试工具 |

### Agent Loop 核心流程

```
agentLoop(prompts, context, config, signal, streamFn)
  │
  ├─ emit(agent_start)
  ├─ emit(turn_start)
  │
  ├─ streamAssistantResponse()     ← 调用 LLM
  │   ├─ transformContext()        ← 上下文变换（压缩等）
  │   ├─ convertToLlm()           ← AgentMessage[] → Message[]
  │   └─ streamFn(model, ctx)     ← 实际 API 调用
  │
  ├─ executeToolCalls()            ← 并行或顺序执行工具
  │   ├─ prepareToolCall()         ← 参数校验 + beforeToolCall
  │   ├─ tool.execute()            ← 实际执行
  │   └─ finalizeExecutedToolCall() ← afterToolCall
  │
  ├─ emit(turn_end)
  ├─ getSteeringMessages()         ← 检查插话
  └─ loop / getFollowUpMessages() / break
```

### Agent 类：有状态的 Loop 包装器

```typescript
class Agent {
  state: AgentState;              // 当前状态
  prompt(msg);                    // 发起新对话
  continue();                     // 从当前上下文续跑
  steer(msg);                     // 插入引导消息
  followUp(msg);                  // 追加后续消息
  abort();                        // 中断当前运行
  subscribe(listener);            // 订阅生命周期事件
}
```

**本层依赖 pi-ai，不依赖 coding-agent 或 tui。**

## 五、L3: pi-coding-agent — 编程 Agent 实现

**职责**：把通用 Agent Loop 变成一个**能写代码的助手**。定义编程工具（Read/Bash/Edit/Write）、会话管理、扩展系统、系统提示词。

### 核心文件

| 文件 | 职责 |
|------|------|
| `src/core/agent-session.ts` | **AgentSession**：编程 Agent 的核心会话类（~3500 行） |
| `src/core/tools/` | 工具定义：`createBashTool` / `createEditTool` / `createReadTool` / `createWriteTool` 等 |
| `src/core/extensions/` | 扩展系统：JS/TS 插件加载、生命周期钩子 |
| `src/core/session-manager.ts` | 会话持久化：append-only 日志 + 树结构 |
| `src/core/compaction/` | 上下文压缩：切割点 + 摘要生成 |
| `src/core/model-registry.ts` | 模型注册表 |
| `src/core/model-runtime.ts` | 模型运行时（鉴权 + API key 管理） |
| `src/core/skills.ts` | Skill 系统：Markdown 驱动的能力注入 |
| `src/core/system-prompt.ts` | 系统提示词构建 |
| `src/core/sdk.ts` | 编程 SDK：`createAgentSession` / `createCodingTools` |
| `src/modes/interactive/` | 交互模式：TUI 组件层 |
| `src/modes/print-mode.ts` | 打印模式（非交互） |
| `src/modes/rpc/` | RPC 模式（远程调用） |
| `src/main.ts` | CLI 入口 |

### 工具系统

每个工具遵循五段式结构：

```
ToolDefinition → 参数 Schema → 参数校验 → execute() → 结果格式化
```

```typescript
// 典型工具定义
const bashTool = createBashToolDefinition({
  spawnContext: { cwd: process.cwd() },
  operations: createLocalBashOperations(),
});
```

### 会话管理

```
SessionManager
├── append-only 事件日志（每条消息追加写入）
├── 树结构分支（fork/switch）
├── 持久化到 SQLite
└── 自动压缩（上下文超限时触发）
```

**本层依赖 agent-core + pi-ai + tui + protocol + client。**

## 六、L4: pi-tui — 终端 UI

**职责**：提供终端 UI 差分渲染引擎，让 Pi 在终端中呈现丰富的交互界面。

### 核心文件

| 文件 | 职责 |
|------|------|
| `src/tui.ts` | TUI 核心：组件树 + 焦点管理 + 叠加层 |
| `src/tui-main-screen.ts` | 主屏幕渲染 |
| `src/tui-alt-screen.ts` | 全屏搜索模式 |
| `src/terminal.ts` | 终端抽象接口 |
| `src/terminal-image.ts` | 图片渲染（Kitty / iTerm2 协议） |
| `src/components/` | UI 组件库 |
| `src/components/markdown.ts` | Markdown 渲染 |
| `src/components/editor.ts` | 文本编辑器 |
| `src/components/scroll-view.ts` | 滚动视图 |
| `src/components/select-list.ts` | 选择列表 |
| `src/keybindings.ts` | 键绑定管理 |
| `src/keys.ts` | 键盘输入解析（支持 Kitty 协议） |
| `src/fuzzy.ts` | 模糊匹配 |
| `src/autocomplete.ts` | 自动补全 |

### 组件树架构

```
TUI (Container)
├── MainScreen
│   ├── ScrollView
│   │   ├── Markdown (assistant 消息)
│   │   ├── Text (user 消息)
│   │   └── ToolExecution (工具执行状态)
│   ├── Editor (输入框)
│   └── Footer (状态栏)
└── AltScreen (叠加层)
    ├── ModelSelector
    ├── SessionSelector
    └── SettingsList
```

### 差分渲染

TUI 不做全屏重绘，而是计算 **新旧帧的差异**，只重绘变化的行。这保证了高帧率和低 CPU 占用。

**本层不依赖任何上层包。它是最底层的 UI 基础设施。**

## 九、环境搭建指南

### 前置条件

```bash
# Node.js ≥22.19
node --version   # v22.x.x

# npm（Pi 用 npm workspaces）
npm --version

# TypeScript（可选，Pi 用 tsgo 编译）
npx tsc --version
```

### 步骤 1：克隆 Pi 源码

```bash
git clone https://github.com/earendil-works/pi.git
cd pi
```

### 步骤 2：安装依赖

```bash
npm install
```

### 步骤 3：构建（按顺序）

```bash
# 按依赖顺序构建
npm run build
```

或者手动按层级构建：

```bash
# L1: pi-ai
cd packages/ai && npm run build && cd ../..

# L2: agent-core
cd packages/agent && npm run build && cd ../..

# L4: tui
cd packages/tui && npm run build && cd ../..

# L3: coding-agent
cd packages/coding-agent && npm run build && cd ../..
```

### 步骤 4：运行实验

```bash
# 回到实验仓库
cd /path/to/pi-agent-loop-labs

# 安装实验依赖
npm install

# 运行所有实验
npm test

# 运行特定实验（如 L03）
npm run test:1
```

### 步骤 5：阅读源码

推荐用 VS Code 打开 Pi 源码，安装 Biome 插件：

```bash
code /path/to/pi
```

源码阅读顺序建议：

```
1. packages/agent/src/types.ts          ← 先看类型定义
2. packages/agent/src/agent-loop.ts     ← 核心循环
3. packages/agent/src/agent.ts          ← 有状态包装
4. packages/ai/src/models.ts            ← 模型定义
5. packages/coding-agent/src/core/tools/ ← 工具实现
```
