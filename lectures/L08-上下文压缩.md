## 详细讲解

### 1. 压缩触发公式与 CompactionSettings

源码将触发配置抽象为 `CompactionSettings` 接口，而非硬编码常量：

```typescript
export interface CompactionSettings {
  enabled: boolean;        // 是否启用自动压缩
  reserveTokens: number;   // 保留给摘要 prompt 和输出的 token 数
  keepRecentTokens: number;// 压缩后保留的近期 token 数
}

export const DEFAULT_COMPACTION_SETTINGS: CompactionSettings = {
  enabled: true,
  reserveTokens: 16384,
  keepRecentTokens: 20000,
};

export function shouldCompact(
  contextTokens: number,
  contextWindow: number,
  settings: CompactionSettings
): boolean {
  if (!settings.enabled) return false;
  return contextTokens > contextWindow - settings.reserveTokens;
}
```

**设计要点**：
- `enabled` 开关允许上层随时禁用压缩（例如用户手动触发时）
- `reserveTokens` 同时用于阈值计算和摘要生成的 maxTokens 上限（`Math.floor(0.8 * reserveTokens)`）
- `keepRecentTokens` 控制切割点算法保留多少近期上下文

### 2. 切割点算法

实际代码使用 `findValidCutPoints` 预扫描合法切点，再从尾部回溯找到最佳位置：

```typescript
// 预扫描：收集所有合法的切点索引
function findValidCutPoints(entries: Entry[], startIndex: number, endIndex: number): number[] {
  const cutPoints: number[] = [];
  for (let i = startIndex; i < endIndex; i++) {
    const entry = entries[i];
    switch (entry.type) {
      case "message": {
        const role = entry.message.role;
        // user / assistant / bashExecution / custom 等可切
        // toolResult 不可切
        if (role !== "toolResult") {
          cutPoints.push(i);
        }
        break;
      }
      // compaction / thinking_level_change / model_change 等元数据条目不可切
      case "thinking_level_change":
      case "model_change":
      case "active_tools_change":
      case "compaction":
      case "branch_summary":
      case "custom":
        break;
    }
  }
  return cutPoints;
}

// 主算法：从尾部回溯，累计 token 超过阈值后取最近的合法切点
export function findCutPoint(
  entries: Entry[],
  startIndex: number,
  endIndex: number,
  keepRecentTokens: number,
): CutPointResult {
  const cutPoints = findValidCutPoints(entries, startIndex, endIndex);
  if (cutPoints.length === 0) {
    return { firstKeptEntryIndex: startIndex, turnStartIndex: -1, isSplitTurn: false };
  }

  let accumulatedTokens = 0;
  let cutIndex = cutPoints[0]; // 默认取第一个合法点

  // 从尾部回溯累计 token
  for (let i = endIndex - 1; i >= startIndex; i--) {
    const entry = entries[i];
    if (entry.type !== "message") continue;
    accumulatedTokens += estimateTokens(entry.message as AgentMessage);
    if (accumulatedTokens >= keepRecentTokens) {
      // 找到 >= i 的最近合法切点
      for (let c = 0; c < cutPoints.length; c++) {
        if (cutPoints[c] >= i) {
          cutIndex = cutPoints[c];
          break;
        }
      }
      break;
    }
  }

  // 回退到紧邻 compaction/元数据之前的位置
  while (cutIndex > startIndex) {
    const prevEntry = entries[cutIndex - 1];
    if (prevEntry.type === "compaction" || prevEntry.type === "message") break;
    cutIndex--;
  }

  // 判断是否为 split turn
  const cutEntry = entries[cutIndex];
  const isUserMessage = cutEntry.type === "message" && cutEntry.message.role === "user";
  const turnStartIndex = isUserMessage ? -1 : findTurnStartIndex(entries, cutIndex, startIndex);

  return {
    firstKeptEntryIndex: cutIndex,
    turnStartIndex,
    isSplitTurn: !isUserMessage && turnStartIndex !== -1,
  };
}
```

### 3. toolResult 不切割约束

```
合法切割点:  user / assistant(stopReason="stop") / bashExecution / custom / branchSummary
非法切割点:  toolResult / assistant(stopReason="toolUse") / compaction / thinking_level_change

原因: toolResult 必须紧跟对应的 toolCall，切割后 toolResult 悬空会导致 API 报错
```

### 4. Split Turn 处理

当切割点落在一个 turn 的中间时（例如 assistant 回复了一半被切掉），Pi 会生成一个**前缀摘要**来补充上下文：

```typescript
export interface CompactionPreparation {
  messagesToSummarize: AgentMessage[];   // 历史消息 → 生成主摘要
  turnPrefixMessages: AgentMessage[];    // 被切掉的 turn 前缀 → 生成前缀摘要
  retainedTail: AgentMessage[];          // 保留的近期消息
  isSplitTurn: boolean;                  // 是否切割了 turn
  tokensBefore: number;                  // 压缩前 token 数
  previousSummary?: string;              // 迭代压缩时的上一轮摘要
  fileOps: FileOperations;              // 文件操作追踪
  settings: CompactionSettings;         // 压缩配置
}
```

**Split Turn 的摘要合成**：
```
历史主摘要（来自 messagesToSummarize）
---
Turn Context (split turn):
前缀摘要（来自 turnPrefixMessages）

两个摘要的 Usage 合并为总 Usage
```

前缀摘要专用 Prompt（`TURN_PREFIX_SUMMARIZATION_PROMPT`）：
```
This is the PREFIX of a turn that was too large to keep.
The SUFFIX (recent work) is retained.

## Original Request
[What did the user ask for in this turn?]

## Early Progress
- [Key decisions and work done in the prefix]

## Context for Suffix
- [Information needed to understand the retained recent work]
```

**调用流程**：
1. `prepareCompaction()` → 判断 `isSplitTurn`、计算切割位置、提取 messages
2. `compact()` → 若 `isSplitTurn`：先调 `generateSummaryWithUsage` 生成历史摘要，再调 `generateTurnPrefixSummary` 生成前缀摘要，最后拼接

### 6. 迭代式压缩与结构化摘要格式

**迭代原理**：每次压缩都会读取上一轮的 `CompactionEntry.summary` 作为 `previousSummary`，将其与新消息一起送入 LLM，生成更新后的摘要（摘要的摘要）。

```
首次压缩:  [历史消息] → SUMMARIZATION_PROMPT → 摘要A
再次压缩:  [新消息 + 摘要A] → UPDATE_SUMMARIZATION_PROMPT → 摘要B
第三次压缩: [新消息 + 摘要B] → UPDATE_SUMMARIZATION_PROMPT → 摘要C
```

**结构化摘要格式**（`SUMMARIZATION_PROMPT`）：

```
## Goal
[What is the user trying to accomplish?]

## Constraints & Preferences
- [Any constraints, preferences, or requirements mentioned by user]
- [Or "(none)" if none were mentioned]

## Progress
### Done
- [x] [Completed tasks/changes]
### In Progress
- [ ] [Current work]
### Blocked
- [Issues preventing progress, if any]

## Key Decisions
- **[Decision]**: [Brief rationale]

## Next Steps
1. [Ordered list of what should happen next]

## Critical Context
- [Any data, examples, or references needed to continue]
```

**迭代更新 Prompt**（`UPDATE_SUMMARIZATION_PROMPT`）的规则：
- PRESERVE 所有已有信息
- ADD 新进展、新决策
- UPDATE Progress：已完成项从 "In Progress" 移到 "Done"
- UPDATE "Next Steps"
- 保留精确的文件路径、函数名、错误消息

### 7. Token 计数：精确 vs 估算（ContextUsageEstimate）

Pi 采用**双轨计数**策略——优先使用 provider 返回的精确 token 数，不足部分用字符估算补齐：

```typescript
export interface ContextUsageEstimate {
  tokens: number;          // 估算的总 context tokens
  usageTokens: number;     // 来自 provider usage 的精确 token 数
  trailingTokens: number;  // provider 报告之后新增消息的估算 token 数
  lastUsageIndex: number | null; // 提供 usage 的消息索引
}

export function estimateContextTokens(messages: AgentMessage[]): ContextUsageEstimate {
  const usageInfo = getLastAssistantUsageInfo(messages);

  if (!usageInfo) {
    // 没有可用的 provider usage，全部估算
    let estimated = 0;
    for (const message of messages) {
      estimated += estimateTokens(message);
    }
    return { tokens: estimated, usageTokens: 0, trailingTokens: estimated, lastUsageIndex: null };
  }

  // 有 provider usage：精确值 + 尾部估算
  const usageTokens = calculateContextTokens(usageInfo.usage);
  let trailingTokens = 0;
  for (let i = usageInfo.index + 1; i < messages.length; i++) {
    trailingTokens += estimateTokens(messages[i]);
  }

  return {
    tokens: usageTokens + trailingTokens,
    usageTokens,
    trailingTokens,
    lastUsageIndex: usageInfo.index,
  };
}
```

**estimateTokens 的图片处理**：

```typescript
const ESTIMATED_IMAGE_CHARS = 4800; // 图片固定估算 4800 字符

function estimateTextAndImageContentChars(content: string | Array<{ type: string; text?: string }>): number {
  if (typeof content === "string") return content.length;

  let chars = 0;
  for (const block of content) {
    if (block.type === "text" && block.text) {
      chars += block.text.length;
    } else if (block.type === "image") {
      chars += ESTIMATED_IMAGE_CHARS; // 每张图 = 4800 chars ≈ 1200 tokens
    }
  }
  return chars;
}
```

**各角色的 token 估算**：
| 角色 | 估算方式 |
|------|----------|
| user | content 文本长度 + 图片 4800 chars/张，÷ 4 |
| assistant | text + thinking + toolCall(name+args) 长度，÷ 4 |
| toolResult | content 文本 + 图片，÷ 4 |
| bashExecution | command + output 长度，÷ 4 |
| branchSummary / compactionSummary | summary 长度，÷ 4 |

### 8. File Operations 追踪

压缩过程中会追踪文件读写操作，记录在 `CompactionDetails` 中，供后续压缩迭代累加：

```typescript
export interface CompactionDetails {
  readFiles: string[];      // 压缩历史中读过的文件
  modifiedFiles: string[];  // 压缩历史中修改过的文件
}

function extractFileOperations(
  messages: AgentMessage[],
  entries: Entry[],
  prevCompactionIndex: number,
): FileOperations {
  const fileOps = createFileOps();
  // 先累加上一轮 compaction 记录的文件操作
  if (prevCompactionIndex >= 0) {
    const prevCompaction = entries[prevCompactionIndex] as CompactionEntry;
    if (prevCompaction.details) {
      const details = prevCompaction.details as CompactionDetails;
      if (Array.isArray(details.readFiles)) {
        for (const f of details.readFiles) fileOps.read.add(f);
      }
      if (Array.isArray(details.modifiedFiles)) {
        for (const f of details.modifiedFiles) fileOps.edited.add(f);
      }
    }
  }
  // 再从当前消息中提取
  for (const msg of messages) {
    extractFileOpsFromMessage(msg, fileOps);
  }
  return fileOps;
}
```

文件操作列表会被格式化并追加到摘要末尾：

### 10. completeSimpleWithRetries 重试逻辑

摘要生成使用独立的重试封装，关键设计：**隔离缓存写入和请求路由**：

```typescript
export async function completeSimpleWithRetries(
  models: Models,
  model: Model<Api>,
  context: Context,
  options: SimpleStreamOptions,
  retry?: RetryPolicy,
  callbacks?: RetryCallbacks,
): Promise<AssistantMessage> {
  const requestOptions: SimpleStreamOptions = {
    ...options,
    cacheRetention: "none",    // 摘要是独立请求，禁止缓存写入（无法复用）
    sessionId: uuidv7(),       // 每次摘要用新 session ID，避免路由复用
  };
  return retryAssistantCall(
    () => models.completeSimple(model, context, requestOptions),
    retry,
    requestOptions.signal,
    callbacks,
  );
}
```

**设计要点**：
- `cacheRetention: "none"`：摘要内容不会被后续请求复用，写缓存浪费资源
- `sessionId: uuidv7()`：每次生成新 ID，确保请求路由不走缓存命中
- `retryAssistantCall`：底层重试框架，处理 transient 错误
- 错误处理：`aborted` → `CompactionError("aborted")`，`error` → `CompactionError("summarization_failed")`

### 11. 完整调用链路

```
shouldCompact()
  ↓ true
prepareCompaction(pathEntries, settings)
  ├── findCutPoint() → CutPointResult
  ├── split messages: messagesToSummarize / turnPrefixMessages / retainedTail
  ├── extractFileOperations()
  └── return CompactionPreparation
  ↓
compact(preparation, models, model, ...)
  ├── 若 isSplitTurn:
  │   ├── generateSummaryWithUsage(messagesToSummarize) → 历史摘要
  │   ├── generateTurnPrefixSummary(turnPrefixMessages) → 前缀摘要
  │   └── summary = 历史摘要 + "\n---\n" + 前缀摘要
  ├── 否则:
  │   └── generateSummaryWithUsage(messagesToSummarize) → 摘要
  ├── computeFileLists() → 追加文件操作到摘要末尾
  └── return CompactResult
  ↓
创建 CompactionEntry (summary, tokensBefore, details, retainedTail)
```

## 例题

**题目**：实现一个简化版的上下文压缩函数，当消息超过阈值时，将早期消息合并为摘要。

**参考答案**：

```typescript
function compactMessages(
  messages: Message[],
  maxTokens: number
): { messages: Message[]; compacted: boolean } {
  const totalTokens = messages.reduce((sum, m) => sum + estimateTokens(m), 0);

  if (totalTokens <= maxTokens) {
    return { messages, compacted: false };
  }

  // 找到需要保留的消息数量
  let tokensFromEnd = 0;
  let keepFromIndex = messages.length;

  for (let i = messages.length - 1; i >= 0; i--) {
    tokensFromEnd += estimateTokens(messages[i]);
    if (tokensFromEnd >= maxTokens * 0.6) {
      keepFromIndex = i;
      break;
    }
  }

  // 生成摘要
  const messagesToCompact = messages.slice(0, keepFromIndex);
  const summary = generateSummary(messagesToCompact);

  // 返回压缩后的消息
  return {
    messages: [
      { role: "system", content: summary },
      ...messages.slice(keepFromIndex),
    ],
    compacted: true,
  };
}

function estimateTokens(message: Message): number {
  // 简化的 token 估算
  return Math.ceil(JSON.stringify(message).length / 4);
}

function generateSummary(messages: Message[]): string {
  const userCount = messages.filter(m => m.role === "user").length;
  const assistantCount = messages.filter(m => m.role === "assistant").length;
  return `[压缩摘要] 包含 ${userCount} 个用户问题和 ${assistantCount} 个助手回复。`;
}
```
